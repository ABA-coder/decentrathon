## 📌 Проблема

Портал госзакупок Казахстана (goszakup.gov.kz) ежегодно обрабатывает **>3 млн тендеров** на сумму **>10 трлн тенге**. Ручная проверка каждого — невозможна. Аудиторы ККСОН, АФМ и Счётного комитета вынуждены работать реактивно, проверяя тендеры уже после нарушений.

**ProcureAI KZ** делает контроль проактивным: система автоматически приоритизирует тендеры с признаками нарушений ещё до подписания контракта.

---

## 💡 Решение

Двухуровневый детектор аномалий + GPT-4o для объяснения каждого решения аудитору:

```
Тендер → Rule Engine (6 правил) ──┐
                                   ├─→ Risk Score [0-100] → GPT-4o Нарратив → Аудитор
Тендер → Isolation Forest ML ─────┘
```

### Типы выявляемых аномалий

| Код | Аномалия | Признак |
|-----|----------|---------|
| A1 | Единственная заявка | `bid_count == 1` |
| A2 | Завышение начальной цены | `price_markup_pct > 30%` |
| A3 | Сжатые сроки подачи | `submission_days < 5` |
| A4 | Повторяющийся победитель | `repeat_winner == 1` |
| A5 | Дробление лота | `lot_count >= 8` |
| A6 | ТЗ под конкретного поставщика | `spec_tailored == 1` |

## 🏗️ Архитектура

```
procure-ai/
├── backend/
│   ├── main.py                  # FastAPI entrypoint
│   ├── api/
│   │   └── routes.py            # REST endpoints (7 штук)
│   ├── core/
│   │   └── explainer.py         # GPT-4o объяснение (structured JSON)
│   ├── models/
│   │   └── detector.py          # Rule Engine + IsolationForest
│   ├── data/
│   │   └── dataset.py           # Синтетика (→ goszakup.gov.kz в prod)
│   ├── requirements.txt
│   └── Dockerfile
├── docker-compose.yml
└── README.md
```

### Стек технологий
- **ML:** Scikit-learn `IsolationForest` (unsupervised, не требует разметки)
- **LLM:** OpenAI GPT-4o (`json_object` mode, `temperature=0.2`)
- **API:** FastAPI + Pydantic v2
- **Данные:** Синтетический датасет 250 тендеров (→ goszakup.gov.kz API в prod)

## 🔑 Ключевые принципы

### 1. Explainability (Объяснимость)
Каждый риск-скор разложен на:
- **Rule layer:** какие именно правила сработали и с каким весом
- **ML layer:** z-score отклонения каждого признака от нормального распределения
- **GPT-4o нарратив:** аудиторское заключение на русском языке с рекомендациями

### 2. AI как поддержка, не решение
- Каждый ответ API содержит явный `disclaimer`
- GPT-4o настроен на `temperature=0.2` для минимизации галлюцинаций
- Система приоритизирует тендеры, но не блокирует их

### 3. Двухуровневая детекция
- **Rule Engine** — прозрачен и аудируем, правила можно изменить
- **Isolation Forest** — выявляет многомерные паттерны, невидимые правилам
- Комбинация: `Risk = 0.55 × Rule + 0.45 × ML`

## ⚠️ Ограничения (Limitations)

| # | Ограничение | Статус |
|---|-------------|--------|
| 1 | **Синтетические данные** — не подключён реальный goszakup.gov.kz API | MVP |
| 2 | **Нет разметки** — IsolationForest unsupervised, `contamination=0.15` выбран эвристически | Требует калибровки |
| 3 | **GPT-галлюцинации** — нарратив требует проверки аудитором | Всегда |
| 4 | **Нет аутентификации** — API открыт, в prod нужен OAuth/JWT | Roadmap |
| 5 | **Отсутствие реестра цен** — A2 (завышение цены) оценивается через `price_markup_pct`, не через реальные рыночные данные | Roadmap |
| 6 | **Язык** — анализ ТЗ (A6) в MVP — флаг в данных, не NLP по тексту документа | V2 |
